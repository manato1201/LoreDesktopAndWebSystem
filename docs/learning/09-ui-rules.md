# 09. UI の決めごと: アクセシビリティ・共通部品・トークン

**この章で分かること**: 「見た目」を場当たりで決めず、**決めごと**にして共通部品に落とす考え方。色だけに頼らない、読み上げに対応する、動きを抑える、といったアクセシビリティの基本。デザイン値(トークン)が、どうやって CSS のクラスになるか。

前提: [08](08-nextjs-frontend.md)(コンポーネントの基本)。

![リポジトリ画面のレイアウト](../diagrams/repo-screen-layout.svg)

## 9.1 「決めていないこと」を無くす

画面が増えると、同じものが違う見た目になりがちです(ある所ではハッシュが12桁、別の所では7桁、など)。そこで、**繰り返し現れる表示は、1か所で決めて、共通部品にします**([`IMPROVEMENT_DESIGN_2026-10.md`](../../IMPROVEMENT_DESIGN_2026-10.md) §3 の「決めごと表」)。

| 項目 | 決め | 実装 |
|---|---|---|
| ハッシュ | 先頭7桁・等幅。クリックで**全体**をコピー+トースト | `CopyableHash`、`lib/format.ts` の `shortHash` |
| 日時 | 相対(「3h ago」)+ホバーと読み上げに絶対時刻(UTC) | `RelativeTime`、API の `Commit.createdAt` |
| 差分 | `+` `~` `−` を**色と併記** | `ChangeTypeBadge`、`lib/change-symbols.ts` |
| 権限(付与済み) | 色に加えて ✓ | `PermissionMatrix` |
| 容量 | 種類別の積み上げバー+凡例。合計=各バケットの和 | `RepositorySummary`、`summarizeStorage` |
| 失敗 | 書き込みの失敗は、理由をトーストで言う | `ApiError`、`mutationErrorMessage` |
| 矢印 | 開閉は下向き、遷移は右向き | `icons.tsx` |

**効果**: 新しい画面を作る人が「どうするんだっけ」と迷わない。直すときも**1か所**で済む(差分の記号を1つ直せば、バッジとビューアの両方が変わる)。

## 9.2 アクセシビリティ: 「見えない人・見分けにくい人」も使える

### ① 色だけに頼らない

色覚の違いや、画面の条件(明るい屋外、白黒印刷)で、色は見分けられないことがあります。**重要な情報は、色以外の手がかり(記号・文字・形)も添えます**。

```tsx
// ChangeTypeBadge(抜粋) — 記号 + 文字 + 色
<span className={`... ${STYLES[type]}`}>
  <span aria-hidden="true" className="font-mono">{CHANGE_SYMBOL[type]}</span>   {/* + ~ − */}
  {LABEL[type]}                                                                  {/* Added / Modified / Deleted */}
</span>
```

`aria-hidden="true"` は、記号を**読み上げさせない**指定です(文字の `Added` が読まれるので、「プラス アディッド」と二重にならない)。

> **確かめ方**: ブラウザの開発者ツールで、画面を**白黒**にしてみる(または色覚シミュレーション)。追加・変更・削除、付与済みかどうかが、まだ分かるか?

### ② 読み上げ(スクリーンリーダー)に対応する

| 道具 | 使い所 |
|---|---|
| `aria-label` | 文字の無いボタンの名前(`aria-label="Copy commit hash …"`) |
| `sr-only`(視覚的に隠すが読み上げる) | `RelativeTime` の絶対時刻 |
| `role="status"` / `aria-live="polite"` | トースト(内容が変わったら、割り込まずに読み上げる) |
| `aria-current="page"` | パンくずの現在地 |
| `aria-pressed` | トグルボタン(権限の付け外し) |
| `role="img"` + `aria-label` | 装飾的な絵(アスキーの木)に、1文の説明 |

**トーストの設計メモ**(`Toast.tsx`): 読み上げ領域(`role="status"`)は、**常に画面に存在させ、中身だけを差し替えます**。出るたびに領域ごと作り直すと、読み上げが拾えないことがあるためです。タイマーは `useRef` に持ち、**新しいトーストが来たら前のタイマーを消し**、画面が消えるときにも片付けます(消し忘れると、消えたはずの画面に `setState` が飛びます)。

### ③ キーボードだけで使える

- すべての操作が、Tab で届き、Enter/Space で実行できる。
- **フォーカスの枠(`:focus-visible`)を消さない**(`globals.css` に全体で指定している)。
- クリックできる所は `<button>` か `<a>` にする(`<div onClick>` はキーボードで届かない)。

### ④ 動きは、控えめに・止められるように

- 動きを付けるなら、`transform` と `opacity` だけ(`top`/`width` を動かすと重い)。
- **`prefers-reduced-motion`**(OS の「視覚効果を減らす」)を尊重する。このシステムの方針は「**自動で**対応する」(ボタンで止めさせるのではなく)。
- 1画面で使う動きは2種類まで。通常の画面は静かに保つ。
- アスキーの木は**静止画1枚**で、動きが無いので、この配慮自体が要りません(動きを足すなら、そのとき対応する)。

### ⑤ コントラスト(文字と背景の明るさの差)

本文の文字は、背景に対して **4.5 : 1 以上**(WCAG AA)が目安です。このシステムの配色を、実際に計算しました(下の `contrast.py` の式で)。

| 組み合わせ | 比 | 判定 |
|---|---|---|
| 本文(白)× カード背景 | 17.76 | ◎ |
| 副文(灰)× 背景 | 8.93 | ◎ |
| 副文(灰)× カード背景 | 8.47 | ◎ |
| アクセント(緑)× カード背景 | 9.25 | ◎ |
| 黒 × アクセント(主ボタン) | 10.94 | ◎ |
| バッジ(追加・緑)の文字 × 薄い緑の背景 | 6.95 | ○ |
| バッジ(変更・黄)の文字 × 薄い黄の背景 | 6.72 | ○ |
| バッジ(削除・赤)の文字 × 薄い赤の背景 | 5.08 | ○(余裕が小さい) |
| バッジ(情報・青)の文字 × 薄い青の背景 | 5.06 | ○(余裕が小さい) |
| **枠線 × カード背景** | **2.10** | △ 非テキスト(境界線)は 3:1 が目安なので、境界だけに頼る UI には不足 |

```python
def srgb_to_linear(c):
    c /= 255
    return c / 12.92 if c <= 0.03928 else ((c + 0.055) / 1.055) ** 2.4

def luminance(hex_):
    r, g, b = (int(hex_.lstrip("#")[i:i + 2], 16) for i in (0, 2, 4))
    return 0.2126 * srgb_to_linear(r) + 0.7152 * srgb_to_linear(g) + 0.0722 * srgb_to_linear(b)

def ratio(fg, bg):
    a, b = luminance(fg), luminance(bg)
    return (max(a, b) + 0.05) / (min(a, b) + 0.05)

ratio("#000000", "#ffffff")        # 21.0(最大)
```

> **配色を変えるとき**(例: アクセントを別の色に): `tokens.json` を直す前に、この式で、**全部の組み合わせ**を計算します。見た目で決めると、細かい文字が読めなくなる色を選びがちです。

## 9.3 トークン: 値に名前を付ける

色・角丸・余白を、コードに**直接書かず**、名前で参照します([11章](11-tooling-and-ci.md)のパイプラインで生成)。

```
tokens.json     { "css": "--color-surface", "value": "#181818" }
   ↓ 生成
tokens.generated.css     :root { --color-surface: #181818; ... }
   ↓ globals.css の @theme inline が、名前を Tailwind に教える
@theme inline { --color-surface: var(--color-surface); ... }
   ↓
クラスで使える:   <div className="bg-surface text-text-secondary rounded-comfortable">
```

- **Tailwind v4** は、`@theme` に書いた名前から、`bg-○○`・`text-○○`・`rounded-○○` のクラスを**自動で作ります**。`bg-surface` は `--color-surface` を使う、という対応です。
- `bg-accent/15` の `/15` は「透明度 15%」。バッジの薄い背景に使っています。
- **色を直接書かない**(`#181818` や `bg-[#181818]` は禁止)。直書きすると、トークンを変えても、その場所だけ古い色が残ります。

### z-index は10刻みで管理

`QUALITY_STANDARDS.md` の約束: ヘッダー 100、ドロップダウン 200、モーダル 1000、**トースト 1100**(モーダルの上)。`9999` のような行き当たりばったりの値は付けない。重なり順を、**一覧で追える**ようにするためです。

## 9.4 共通部品の作り方(レシピ)

新しい部品を足すときの型です。例として「ロック中バッジ」を考えます。

1. **決めごとを先に決める**: 何を表すか、色だけに頼らないか(🔒のようなアイコン+文字)、読み上げは?
2. **ロジックは `lib/` へ**: 表示に必要な計算や文言(例: 「Locked by Aiko」の組み立て)を、純粋な関数にして**テストを書く**(サーバーコンポーネントは単体テストしにくい。[08](08-nextjs-frontend.md))。
3. **部品はトークンのクラスだけで**書く。色や余白を直書きしない。
4. **使う側を揃える**: 同じ意味の表示が他にあれば、その部品に置き換える(重複を残さない)。
5. **失敗の経路も作る**: 書き込みを伴うなら、失敗時に理由を出す(`mutationErrorMessage` + トースト)。送信中の状態は `finally` で戻す。

## 9.5 まとめ

- 繰り返す表示は**決めごと**にして共通部品へ。直すのが1か所で済む。
- 色だけに頼らない。読み上げ・キーボード・動きの抑制・コントラストを守る。
- 値は**トークン**に名前を付けて参照。直書きしない。
- 部品は、**決めごと → ロジック(テスト) → 見た目 → 置き換え → 失敗経路**の順で作る。

## 9.6 演習

1. 画面を白黒にして(開発者ツールのレンダリング設定)、コミット詳細ページとアクセス制御ページを見る。色が無くても、追加・変更・削除、付与済みの権限が区別できることを確かめる。
2. スクリーンリーダー(Windows のナレーター)で、コミット詳細ページのハッシュのボタンと日時を読み上げさせる。どう読まれるか。
3. `Toast.tsx` を読み、`showToast` を**連続して2回**呼ぶと、1回目のタイマーはどうなるか説明する。(ヒント: `clearTimeout`。)
4. **計算**: アクセントを `#1ed760` から `#7cf2a0` に変えたら、「黒 × アクセント」と「アクセント × カード背景」のコントラスト比はどうなるか。`contrast.py` の式で計算し、判定を書く。
5. **実装**: ファイルがロックされているとき、ツリーの行に「鍵のアイコン+ `Locked by 名前`」を出す、`LockBadge` の**ロジック部分**(`lib/lock-label.ts`)とテストを書く。色だけに頼らない設計にする。
6. **発展**: 枠線のコントラスト(2.10)を 3:1 以上にするには、`--color-border` をどのくらい明るくすればよいか。変えたとき、他の画面の見た目はどう変わるか。
